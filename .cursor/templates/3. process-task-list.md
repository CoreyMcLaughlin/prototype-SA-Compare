# Task List Management

## Overview

Guidelines for managing task lists in markdown files to track progress on completing a PRD.

**User testing path only.** On the concept path in `prototype-workflow.mdc`, do not save a task list file and do not stop after each parent task for permission. This file applies when a saved task list exists.

If the PRD includes a Figma link, use the Figma MCP to inspect designs and extract specs before building.

## Task Implementation

- **One task at a time:** Do **NOT** start the next task until you ask the user for permission and they say "yes" or "y"
- **Completion protocol:**
  1. When you finish a **sub‑task**, immediately mark it as completed by changing `[ ]` to `[x]`.
  2. If **all** subtasks underneath a parent task are now `[x]`:
    - **Clean up**: Remove any temporary files or debugging code
    - **Check the browser**: Make sure the prototype looks right and the flow works
    - **Offer code review**: Ask the user if they would like a quick review:
      > "Parent task complete! Want me to do a quick review before moving on?
      > - Reply **'review'** and I'll check it against the PRD
      > - Reply **'next'** to keep going"
    - If user wants review: Check the implementation against the PRD requirements and flag anything missing or off-brand.
  3. Once all subtasks are marked complete, mark the **parent task** as completed.
- Stop after each sub‑task and wait for the user's go‑ahead.

## Task List Maintenance

1. **Update the task list as you work:**
   - Mark tasks and subtasks as completed (`[x]`) per the protocol above.
   - Add new tasks as they emerge.

2. **Maintain the "Relevant Files" section:**
   - List every file created or modified.
   - Give each file a one‑line description of its purpose.

## AI Instructions

When working with task lists, the AI must:

1. Regularly update the task list file after finishing any significant work.
2. Follow the completion protocol:
   - Mark each finished **sub‑task** `[x]`.
   - Mark the **parent task** `[x]` once **all** its subtasks are `[x]`.
3. Add newly discovered tasks.
4. Keep "Relevant Files" accurate and up to date.
5. Before starting work, check which sub‑task is next.
6. After implementing a sub‑task, update the file
7. Ask for user approval to continue after building significant tasks or if it needs testing

## When a task is done

Ask the designer if they're happy with it. If yes, move to the next task.
